I. Software Design 
1. High Level Design 
1.1 Software Architecture 
The EWMS follows a layered client-server architecture. The   React 18 frontend   provides the user
interface for system users and communicates with the   ASP.NET Core Web API   through   RESTful APIs .
The backend contains controllers and services that handle requests, business logic, authentication,
authorization, and email-related operations. The Data Access Layer uses   Entity Framework Core , 
4 | Page 
--- PAGE 5 ---
repositories, and   DbContext   to access the   SQL Server database .   Barcode/QR scanners   and   thermal
label printers   support warehouse operations such as receiving goods, dispatching goods, and printing
labels.

3.8 State machine diagram 
Develop a state chart diagram for at least one business object that exhibits state-dependent behavior. 
Please note that the state chart must be implemented and demonstrated as part of your demo. 
110 | Page 
--- PAGE 111 ---
The Inventory Sheet State Machine Diagram describes the lifecycle of an inventory counting sheet in
the EWMS. After an Inventory Sheet is created, Warehouse Staff perform the physical counting
process. When all quantities are valid, the sheet is submitted and its status changes to   Pending
Approval . The Manager can approve or reject the sheet. If approved, the system adjusts the stock
and the sheet moves to the   Approved   state. If rejected, Warehouse Staff can perform a recount and
return the sheet to the   Created / Counting   state. The sheet can also be cancelled before submission,
which moves it to the   Cancelled   state.

Pending Approval   →   Approved   Approve / Adjust Stock   Stock is updated 
Pending Approval   →   Rejected   Reject   Sheet is rejected 
Rejected   →   Created / Counting   Recount   Staff counts again
